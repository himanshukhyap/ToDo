# NoteTask — Android app (React Native / Expo)

The native Android version of NoteTask. It lives next to the web app and does not change it:
the web app (`../src`, Vite, Firebase Hosting) builds and deploys exactly as before.

Both apps use the same Firebase project (`todo-ec064`) and the same Firestore collections,
so tasks, notes and notebooks sync between web and phone.

## Features (same as web)

- Google sign-in (native account picker) and email sign in / register / forgot password
- Tasks: categories, subtasks, swipe left to edit/delete, share/copy, pending/done tabs, search, delete all
- Notes: coloured cards, rich text (bold, italic, underline, strike, lists), read more, share/copy
- Notebook: notebooks → sections → pages, rich text editor with 800 ms autosave
- Trash: notes / tasks / notebook trash, restore, delete permanently, auto-clean after 30 days
- Admin panel: backup (shared as a JSON file), restore from a file with duplicate skip, session settings
- Dark / light theme, offline / syncing banner

## Requirements

- Node 20+
- JDK 21 (`C:\Program Files\Eclipse Adoptium\jdk-21...`) with `JAVA_HOME` pointing to it
- Android SDK (installed with Android Studio)

## Commands

```bash
cd mobile
npm install

# Run on a connected phone / emulator (development build)
npm run android

# Build an installable release APK
npm run apk
# → android/app/build/outputs/apk/release/app-release.apk
```

`android/` is generated by `expo prebuild` and is git-ignored. Change native settings in `app.json`.

## Notes

- Google sign-in needs the SHA-1 of the signing key registered on the Firebase Android app
  `com.notetask.app` (the release and debug keys are already added). A new signing key needs
  `firebase apps:android:sha:create` before Google sign-in works in that build.
- Microsoft sign-in from the web app uses a browser popup and is not available in the Android app.

## Release signing

Release builds are signed with `credentials/notetask-release.jks`, using the passwords in
`credentials/keystore.properties`. `plugins/withReleaseSigning.js` adds this to the generated
`android/` project. The `credentials/` folder is git-ignored.

**Keep a backup of the `credentials/` folder** (for example on Google Drive or a USB drive). Every
update to the app must be signed with this same key; if it is lost, existing installs cannot be
updated and the app would have to be published again under a new identity.

If `credentials/` is missing, release builds fall back to the debug key.
